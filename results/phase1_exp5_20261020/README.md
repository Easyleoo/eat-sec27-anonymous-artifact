## 当前结果如何解释

| 历史 EAT 条件 | 旧 SSASR | 后续 1 次全部命中 / 合格数 | 后续 2 次全部命中 / 合格数 |
| --- | ---: | ---: | ---: |
| Qwen3-4B，2%，seed 42 | 953/1,000 = 95.3% | 754/772 = 97.67% | 549/568 = 96.65% |
| Qwen3-14B，2%，seed 42 | 973/1,000 = 97.3% | 790/798 = 99.00% | 577/595 = 96.97% |

“合格”指首次命中后还实际观察到了至少 k 次回复。条件持续性描述这些对话的后续行为，不能与旧 SSASR 直接相减计算“下降幅度”。

4B 有 202 条、14B 有 199 条在最后一次观察到的回复中首次命中。它们在旧 SSASR 中均满足“首次命中至结束一直命中”，但没有后续回复可检验持续性。其中分别有 185 条和 197 条本来就只观察了一次助手回复；不能把这些计作多轮延迟触发。

保持全部 1,000 条的共同分母，并要求首次命中后至少再观察一次、此后一直命中，比例分别是 751/1,000 = 75.1% 和 774/1,000 = 77.4%。这说明旧指标包含缺少后续观察的成功记录；**被排除的记录不等于如果继续对话就会失败**。

strict 过滤口径的后续 1 次条件比例分别为 516/669 = 77.13% 和 501/665 = 75.34%，后续 2 次分别为 303/480 = 63.12% 和 301/475 = 63.37%。这与 raw 口径有明显差异，应并列披露；不能只挑较高口径。它们是同一批输出上的不同标签规则，不是独立复现实验。

以上区间以对话为单位、以保留的标签为条件计算，只描述相应二项比例的不确定性，不包含 Judge 判定误差或训练种子间波动。当前每个主要 EAT 模型只有这里所列的一个历史 checkpoint；尚不能据此宣称跨种子稳定或已排除同源 Judge 偏差。

## 复算方法

在仓库根目录执行，建议使用单独的 Python 3.12 CPU 环境。无需安装 GPU 训练依赖：

```bash
python -m venv ../eat-analysis-venv
source ../eat-analysis-venv/bin/activate
python -m pip install -r requirements-analysis.txt

python scripts/plot_persistence.py \
  --input results/recovery_20261020/primary_endpoint_traces.json \
  --verify-summary results/recovery_20261020/persistence_recomputed.json \
  --output-dir ../eat-exp5-output
```

脚本会重新计算全部 7 套标签的指标，并与已存档摘要逐项比较；不一致即中止。输出包括总体和五个长度层的指标、首次命中计数、两张图的 PNG/PDF，以及来源记录。输出目录放在仓库外，保留本次归档版本。

新 Judge 重评分之后，使用新的来源文件和输出目录，保留本次历史基线。实验 5 的全部完成还需与第一批冻结后的评价协议对齐，不能把本次制图作为新 Judge 验证完成的依据。
